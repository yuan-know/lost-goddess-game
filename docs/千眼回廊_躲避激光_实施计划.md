## 0. 一句话结论

青年线的躲避激光就是脚本里的 **PZ_04**：光柱左右横扫，玩家在光柱扫到脚下之前**点击兜帽石像瞬移躲进阴影**，连续躲避走完全程；
暴露在光柱里累计 **3 秒** → 灼烧死亡、回滚重试（判词「目困莽夫，身陷焦土」，重生引导「见影即止，避瞳而行」）。
好消息：**走廊底图（睁眼/闭眼两版）已经在仓库里了**，本关不缺场景美术，缺的是机关件与音频。

## 4. 玩法设计（我的提案）

### 4.1 核心循环（推荐变体 1：推进式）

```
进入长廊(左端) → 盲僧提示
      ↓
【自由行走 + 光柱持续横扫】
      ↓
光柱扫向你所站的位置 → 点最近/前方兜帽石像 → 瞬移进石像脚下阴影（安全）
      ↓
等光柱扫过去（露头窗口）→ 出阴影继续推进
      ↓
反复 N 段 → 抵达右端出口 → 走完全程 → 谜题解开 → 盲僧赠符文【ᚱ 旅程】
```

- **为什么不是"原地节奏关"**：脚本写的是"走完全程"+ 提尔"侧头看向头顶黄铜眼"，玩家主体行为是推进，石像瞬移是保命手段，不是唯一移动方式。变体 1 更贴原文，也更能体现"莽撞闯关 vs 稳健躲避"。
- **石像 = 检查点**：每尊石像既是安全区，也是该段的回滚锚点（见 §8 待拍板项 ①）。

### 4.2 光柱

- 巡逻式：从走廊左端匀速扫到右端，再扫回来（三角波/正弦），有短暂的"折返顿挫"更好读
- 地面危险区 = 光柱中心 X ± 半宽（默认 ±2.0 单位，约 200px）
- 三道视觉层：光柱本体（发光叠加）→ 地面光斑（贴地椭圆/条形）→ 扫过时的地面焦痕辉光
- 命中判定只认**地面光斑与玩家 X 的重叠**（2D 横版单轴判定，简单可读）

### 4.3 阴影与石像

- 每尊兜帽石像脚下有一块阴影安全区（默认半宽 1.2 单位），光柱扫过时站在里面 = 不累计暴露
- 点击石像 → `PlayerController.Teleport(石像阴影中心)`（不是走过去，是"瞬移"——青年专属能力，表演上给 0.15s 的残影/闪身）
- 石像被点击时给高亮 + 石眼暂时闭合的反馈（对应盲僧台词"只有在神像的庇护下，石眼才会暂时闭上"）

### 4.4 暴露与死亡

- 玩家 X 落在光柱地面危险区内 → 开始累计暴露计时
- 计时 **3.0 秒（脚本硬性数值）** 打满 → 触发 D_02：
  闪红 → 焦热扭曲 → 惨叫倒地 → 字幕判词「目困莽夫，身陷焦土」→ 回滚
- 离开危险区后计时**缓慢回退**（默认 1.5× 回退速度），给玩家容错
- 危险预警：暴露开始即屏幕边缘泛红 + 顶部石眼睁开，暴露 ≥1.5s 时加心跳音/画面抖

### 4.5 成功

- 抵达右端出口触发区 → 光柱停摆、石眼全部闭合（切 `bg_closed`）→ `PuzzleBase.Solve()` → 盲僧台词 → 符文【ᚱ 旅程】特写 + 入格

### 4.6 HUD 调试键（照 GearDial 惯例）

```
← →      光柱横扫速度 − / +
[ ]      光柱地面半宽 − / +
; '      暴露阈值(3.0s) − / +     ← 脚本硬数值，只给调试改
, .      暴露回退速度 − / +
P        暂停 / 恢复扫光
1~5      跳到第 N 段（并瞬移到该段石像）
K        强制触发一次死亡（测演出）
T        显示 / 隐藏 危险区 + 安全区 + 石像锚点
R        重置谜题
G / H    唤出 / 隐藏 调试 HUD（**默认隐藏**，游戏画面不再有调试文字）
B        切换 黄铜眼 睁 / 闭（眼睑开合序列帧，不切底图）
```

## 12. 修订（2026-09-14 第三轮）：眼睑遮挡 —— 眼珠滚到极限被压住

### 12.1 需求

> 眼珠转动到极限的时候应该要被眼睑遮挡一部分（注意黄金瞳里面那层才是眼睑，眼睑外面还包裹了一层那个不是真正的眼睑，你需要精准识别遮挡区域）

### 12.2 「真正的眼睑」到底是哪一层

`黄金瞳.psd` 里 **没有任何一层叫"眼睑"**，需要自己从像素里认：

| 层 | 实际内容 |
|---|---|
| 新建组 ▸ 已插入图像 #1 | 成品（外壳+瞳孔），`g0` 与 `g1` 差异 4480px 且 bbox 正好落在瞳孔上 ⇒ `g0 = g1 over g2` |
| 新建组 ▸ 已插入图像 #2 | **外壳 = 金色金属包边 + 眼窝(深色凹坑)**，无瞳 |
| 新建组 ▸ 图层 52 | 瞳孔球（76×70） |

关键判断：**最外圈那层亮金色是金属包边（不是眼睑）**，真正压住眼珠的是**紧贴眼窝开口的那条边**——
在 `bg_eye_shell.png` 上表现为「深色眼窝 → 眼睑亮带」的亮度跃变线。瞳孔根本够不到最外圈，
所以只要把**眼窝开口**抠出来当遮挡边界，就自动等价于"被真正的眼睑压住"。

### 12.3 精准识别方法（逐列梯度法）

首次尝试用"局部均值阈值 + 连通域洪水填充"**失败**——金色包边外侧还有一圈暗轮廓，
暗 → 暗 连通，一填就把整只眼吞掉（面积 95899 px ≈ 半个画布）。

改成**逐列扫描找最大正梯度**：

1. 对每列 x，从瞳孔中心行 y=174 向上/向下扫描 `bg_eye_shell` 的灰度；
2. 5px 平滑后取**最大正梯度**位置 = 「眼窝暗 → 眼睑亮」的跃变点；
3. 要求跃变后亮度 >100（滤掉眼窝内的碎屑高光噪声）；
4. 邻域 ±15px 中值平滑 + 线性插值补洞 → 上缘曲线 `yup(x)` / 下缘曲线 `ybot(x)`；
5. 两端 30px 内按 `sqrt(1-(1-s)²)` 收口，让开口自然收成眼角尖形。

实测结果（裁剪框内 px）：

| 位置 | 上缘 | 下缘 | 开口高 |
|---|---|---|---|
| x=130 | 134 | 235 | 101 |
| x=252（瞳孔中心列） | 104 | 269 | **165** |
| x=400 | 144 | 224 | 80 |

开口左右端 `x = 116 / 414`，`mask` 面积 39539 px（画布 19.8%）。

脚本固化为 **`tools/eye_lid_mask.py`**（可重跑，自带"位移 → 遮挡比例"自检表）。

### 12.4 遮挡层：`bg_eye_lid.png`

```
bg_eye_lid.png = bg_eye_shell.png，但「眼窝开口内」alpha 归零
```

运行时三层（`sortingOrder` 递增）：

| 层 | sortingOrder | 作用 |
|---|---|---|
| `bg_eye_shell` | `ZOrderEye` (30) | 眼窝底 + 外壳 |
| `bg_eye_pupil` | 31 | 瞳孔球 |
| `bg_eye_lid` | **32** | 外壳（挖掉眼窝）→ 瞳孔超出开口的部分被压住 |
| `~eye_glow` | 33 | 柔光（现在跟着瞳孔走） |

### 12.5 摆幅必须跟着放大（这是关键）

实测「瞳孔位移 → 被切掉比例」：

| 位移 | 左移遮挡 | 右移遮挡 |
|---|---|---|
| 0.55 单位（**上一轮的默认值**） | 0% | 0% |
| 0.98 / 1.23 单位 | 0%（刚好贴到眼角） | 0% |
| **1.10 / 1.30 单位** | **17.5%** | **22.6%** |
| 1.30 / 1.50 单位 | 45.8% | 41.0% |

⇒ 原来 ±0.55 的摆幅**根本碰不到眼睑**，必须放大到 ±1.1~1.35 才看得到遮挡。

又因为**瞳孔默认位置偏左于眼窝中心 12.5px**（瞳孔中心 252.5 vs 开口中心 265），
左右可用行程不一样（左 0.985 / 右 1.235），所以摆幅拆成两个：

```csharp
PupilSwingLeft  = 1.105f;   // ← 由 PupilEdgeSwingLeft  反推,±1.10 ≈ 被压掉 17%
PupilSwingRight = 1.355f;   // ← 由 PupilEdgeSwingRight 反推,+1.36 ≈ 被压掉 22%
PupilEdgeSquash = 0.10f;    // 滚到眼角时横向压 10%(球面转动感)
```

`PupilEdgeSwingLeft/Right` 由实测常量算出（`EyeOpeningLeftPx=116 / EyeOpeningRightPx=414 / PupilRadiusInBox=38`），
代码里不用魔法数：`(252.5-(116+38))/100 = 0.985`、`((414-38)-252.5)/100 = 1.235`。

### 13.3 为什么不能沿用「逐列梯度识别开口」

闭眼时整只眼都是亮黄铜 → 瞳孔被完全盖住；睁眼时中间透出瞳孔 → 仍能跟随光柱滚动；

## 14. 修订（2026-09-14 第五轮）：闭眼时激光一并隐藏

### 14.1 需求

### 14.2 原行为 vs 新行为

| | 原行为 | 新行为 |
|---|---|---|
| 闭眼时光柱 | `alpha × 0.35` —— 变淡但仍看得见 | `alpha × 0` —— **完全隐藏** |
| 地面光斑 | 只缩小，alpha 不变（光柱没了光斑还在） | 一起淡出、一起收小 |
| 眼睛柔光 | 叠在眼睑**之上**（order 33 > lid 32），闭眼时眼皮表面浮着一团光晕 | 移到眼睑**之下**（order 31），被合上的眼皮真正挡住 |

### 14.3 淡出曲线（不是直接乘 `_eyeOpen`）

```
lidOpen01 = smoothstep( inverseLerp(0.15, 0.85, _eyeOpen) )
beamK     = lerp(ClosedBeamAlpha, 1, lidOpen01)        // ClosedBeamAlpha 默认 0
```

实测映射（`tools/eye_lid_open_check.py`）：

| `_eyeOpen` | 眼睑帧 | 瞳孔区遮挡 | `beamK` |
|---|---|---|---|
| 1.00 | 19/19 | 1.1% | 1.00 全亮 |
| 0.75 | 14/19 | 1.8% | 0.94 |
| 0.50 | 10/19 | 18.3% | 0.50 |
| 0.25 | 05/19 | 58.0% | 0.06 |
| 0.00 | 00/19 | 71.5% | 0.00 **隐藏** |

出阴影时光柱按同一条曲线淡入（≈ 眼睑睁开的时间），不会"啪"地跳出来。

### 14.4 可调旋钮 / 调试键

### 14.5 公平性说明（重要）

## 15. 修订（2026-09-14 第六轮）：石像庇护的消耗时机 + 瞬移距离

> 起因：用户问「这游戏怎么通过？怎么点击兜帽石像还能闪现过去」

### 15.1 一句话：怎么通关

从长廊左端（`SpawnX = −15.4`）走到右端（`ExitX = +15.4`）→ 触发 `WinRoutine` → 盲僧赠符文【ᚱ Raidho · 旅程】。
中间必须一段一段借**兜帽石像的阴影**躲过横扫的光柱，共 7 尊石像、间距约 4.30~4.40 单位。

```
入口(x=-15.4) → [石像①..⑦ 逐段推进] → 出口(x=+15.4) → 通关
每个"段"的循环:  走进阴影(安全,石眼闭) → 等光柱扫过去 → 出阴影 → 冲下一尊
```

数值对照：玩家走 3.0 单位/秒，光柱 5.5 单位/秒（**比人快**），危险区半宽 2.2 单位，
被照到累计 3.0 秒即死（判词「目困莽夫，身陷焦土」→ 退回入口）。
所以"硬跑"跑不赢，必须借石像。

### 15.2 修掉的漏洞 ①：瞬移进阴影后其实没有庇护

`TryShelter()` 原本在瞬移的**同一瞬间**就把 `s.used = true`，而 `IsStatueAvailable()` 立刻变 false，
`IsShieldedAt()` 也就不认这块阴影了 —— 结果是"闪过去 → 下一帧眼睛就睁开 → 光柱打在你身上"，
**与脚本 N05-Y-060「点击兜帽石像瞬移躲入阴影」直接矛盾**。

改成 **离开阴影的那一刻才消耗**：

```
进过阴影 → s.sheltered = true (闩锁,进入即安全)
走出阴影 → 消耗(StatueOnce 用 used / 否则用 cooldown) + 提示"神像的目光睁开了"
```

于是"点击瞬移"与"走进去"两种方式**语义一致**：进阴影 = 安全（石眼闭、光柱隐藏），
**离开 = 这尊失效**（石眼睁开、光柱显形）。同时这条也顺手补齐了第 14 节留下的公平性缺口。

### 15.3 修掉的漏洞 ②：瞬移距离默认"不限"

`StatueReach = 0` 表示不限距离 → **在入口直接点最右那尊（x=12.95）就能闪过去，再走 2.45 单位即通关**，
整个谜题被跳过。默认改为 **4.6 单位 = 只够到相邻一尊**（石像间距 4.30~4.40），强制逐段推进。

- 够不到的石像：标记与阴影都会**压暗**（`markTarget × 0.30`），点了会提示"太远了,够不到这尊神像。"
- 调试键 `N` 在三档预设间循环：相邻一尊(4.6) → 隔一尊(8.8) → 不限(0)。
- HUD 新增一行：`瞬移距离 / 进度 x N / 出口 N / 剩余石像 N`。

### 15.4 ★ 仍未拍板的平衡漏洞：连点闪现可以零风险过关

瞬移是**瞬间**的，而相邻石像都在 4.6 的射程内 ⇒ 可以"①→②→③…→⑦"连点 6 次，
全程都在阴影里、一次都不会被照到，几秒通关。走过去的路线同样要消耗 7 尊石像，
所以**连点闪现严格优于走路，没有任何代价**。

三个候选解法（**均未实现，等拍板**）：

| 方案 | 做法 | 效果 |
|---|---|---|
| A ★推荐 | 只有**被光柱锁定中**才能瞬移 | 把瞬移钉死成"保命"动作：你必须先被照到（3 秒窗口 = 瞬移窗口），推进只能靠腿，节奏变成「被照到 → 闪 → 再被照到 → 再闪」 |
| B | 庇护**限时**（`ShelterSeconds ≈ 2.5s`，"石眼只暂时闭上"字面化） | 逼你算时间出来；但连点仍然安全，只加难度不加约束 |
| C | 瞬移**冷却** `TeleportCooldown ≈ 1.5s` | 抑制连点速度；同上，等待期间仍在阴影里安全 |

A 是唯一真正关掉漏洞的；B/C 只是加难度。也可以 A+B 一起。

## 17. ★★ 玩法整体重做（2026-09-14 第八轮）—— 「躲光束」

> §0 ~ §16 描述的旧玩法（点石像瞬移躲阴影 + 3 秒暴露 + 灼烧死亡演出 + 眼睑开合）
> **全部作废**。本节是当前唯一生效的设计。

### 17.1 需求原文（用户）

> 青年台词「装神弄鬼。不就是躲个光吗?」之后，直接进入游戏。**这个部分的游戏不设置任何提示 UI**，
> 需要有一个触发游戏失败的回退进度设置。场景不变，但墙壁上增加了一个黄铜眼，光束以铜眼为顶点射出来
> 在场景内左右扫荡（**只有一个光束，宽度大概为三个拱门宽，光束移动速度要快！！**）。
> 玩家需要操控青年从最左侧走到最右侧场外，不能被光束照射到（被找到就进度回退，角色重新出现在最左侧继续）。
> 角色一开始站在最左侧，如果不赶紧操控行动就会被光束照到，直接算"任务失败"，进度回退到最左侧继续。
> 石像之间的拱门处是"安全点"（美术做了遮罩阴影，表示青年躲在了暗处）。走到【右侧场外】即为成功。
> **原来的推翻重做。** 光束会来回照射最左和最右侧；拱门遮罩区域内部视为安全区，即使光束穿过也不会触发失败。
> 这个环节需要玩家快速反应，所以不做什么说明。**光束移动速度调高一倍。眼珠转动和眼睑闭合删去。**

### 17.2 新规则（一句话版）

| | |
|---|---|
| 目标 | 从走廊**最左端**走到**最右端**（`SpawnX=-16.45` → `ExitX=+16.45`，走廊 `[-17, +17]`） |
| 危险 | 铜眼射出**一道**锥形光束，底边贴地、**总宽 7.5 单位（≈ 3 个拱门）**，左右摆荡扫遍两端 |
| 安全 | **8 个拱门暗影内**（美术 `bg_gate_shadow.png`）—— 光束穿过也不失败 |
| 失败 | 被光束照到 → **立刻**闪一下白光 + 人回最左端重来。**没有倒计时、没有判词、没有文字提示** |
| 通关 | 走到最右端 → 走完全程（盲僧赠符文，保留原剧情） |
| UI | **零**。没有 toast、没有红晕、没有危险区提示。判断全靠画面 |

### 17.3 8 个安全点从哪来：`bg_gate_shadow.png` 实测

美术给的遮罩图是 **3400×1200、与 `bg_full.png` 完全同格**（PPU100 / BottomCenter），
本身就是半透明黑（RGB≈0，alpha≈100/255），**直接叠上去**就是"拱门比别处暗一截"。

按列扫 alpha 得到 8 个拱门区间（`tools/check_gate_shadow.py` 可重跑）：

| 1 | 72..311 | −16.280 .. −13.890 | −15.085 | 2.39 |
| 2 | 492..749 | −12.080 .. −9.510 | −10.795 | 2.57 |
| 3 | 930..1178 | −7.700 .. −5.220 | −6.460 | 2.48 |
| 4 | 1358..1606 | −3.420 .. −0.940 | −2.180 | 2.48 |
| 5 | 1783..2041 | +0.830 .. +3.410 | +2.120 | 2.58 |

### 17.4 光束的几何：为什么必须用 Mesh 画

- **顶点固定在铜眼** `(-0.075, 4.30)`；**底边贴着地面** `y=-5.76`、以 `beamX` 为中心、半宽 3.75。
- 这是一个**斜三角形**（顶点在画面中央上方，底边扫到画面边缘时严重倾斜）——
  用等腰 sprite 拼不出来（旋转 + 非等比缩放都会让底边离开地面）。
  所以改成 **3 顶点 `Mesh` 每帧重算**（`MeshRenderer` + 加色材质），外加一层收窄 34% 的"内核"三角。
- 光锥贴图 `ConeTex()` 运行时生成：横向柔边 + 纵向渐隐（UV 顶点=(0.5,1)、底边=(0/1,0)）。

**危险判定与视觉严格一致**：`|playerX - beamX| <= 3.75`。因为光锥底边就贴在地面上，
"点是否在光锥里"在地面上等价于"X 是否落在底边宽度内"，所以判定不需要做三角形求交。

### 17.5 参数与实测节奏（`tools/check_pz04_beam.py` 可重跑）

| 参数 | 值 | 说明 |
|---|---|---|
| `BeamGroundSpeed` | **11.0 单位/秒** | 用户要求"比旧版快一倍"：旧光柱 5.5 → 11 |
| `BeamGroundHalfWidth` | **3.75**（总宽 7.5） | "约三个拱门宽"（拱门 2.49） |
| `BeamTrackMin/Max` | ∓17 | 扫遍两端 |
| 铜眼顶点 → 地面 | 10.06 单位 | 垂直向下时张角 **40.9°**，扫到两端时收窄到 **11.3°** |

实测节奏：

```
光束单程 3.09 秒 / 一个来回 6.18 秒       光带扫过某点 0.68 秒
玩家走完全程 10.97 秒（= 1.8 个光束来回）
安全区之间暴露段 1.75 ~ 1.81 单位 → 跑过去 0.58 ~ 0.60 秒
```

**通关可行性（离线模拟，保守策略 = 只在"整段冲刺都不会被照到"时才出发）：
✓ 12.8 秒通关、0 失误。** 只比莽着跑多 1.8 秒 —— 窗口很紧但存在。
真人做不到完美预判，实际会死几次，这正合"需要快速反应"的设计意图。

### 17.6 一个必须记住的坑：光束**不能**也从左端出发

出生点故意放在第一个安全区（−16.28）**之外**（−16.45）—— 这是为了满足用户
"站着不动就会被照到"。但如果 `ResetRun()` 把光束也初始化在左端，**玩家一出生就在光带里，
连一帧反应时间都没有**（离线模拟里被抓了 695 次、进度 0%）。

修法：**每次重来，光束都从最右端（+17）出发朝左扫**。这样约 2.7 秒后才够到出生点，
这段时间就是"赶紧行动"的窗口；站着不动照样被抓 ✓ 两个要求同时满足。

## 18. 修订（2026-09-14 第九轮）：两片光区 / 散光质感 / 暗影调光 / 死亡判词

### 18.1 「示意图画了两片区域 ⇒ 应该有两片激光在反复移动」

回去把参照图 `2c99e4863255d8dd384210aa7b287e3b.jpg` 用霍夫变换解了一遍：从铜眼顶点
（图中 ≈ px1515,129）发出的线里，有 **4 根特别粗的主线**：

| 角度 | 落地点(参照图像素) | 换算世界 X |
|---|---|---|
| −52.0° | 366 | −12.93 |
| −6.2° | 1433 | −1.08 |
| +27.2° | 2028 | +5.53 |
| +58.5° | 3050 | +16.89 |

⇒ 是**两片锥形光区**：左片张角 −52°…−6°、右片 +27°…+58°，**顶点都在铜眼上**。

实现：`BeamCount = 2`，两片共用一个**三角波相位**，相位差 `BeamPhaseStep = 0.5`
⇒ 永远一片偏左、一片偏右，**镜像对开**（一束朝左时另一束正好朝右）。

**★ 复位相位不能随便取**：镜像是成对的 —— 一束在 −17 另一束必然在 +17，
而出生点在 −16.45，正好落进光带里，开局没反应就死。
所以 `BeamResetX = 9.3`（复位时两束在 ±9.3，出生点还有 **2.02 秒**缓冲），
由 `PhaseForX()` 反算相位（取三角波的下降段 = 朝左走）。

| 光束落点(单位/秒) | 11.0 | 单程 3.09 秒 / 一个来回 6.18 秒 |
|---|---|---|
| 每片总宽 | 7.5 ≈ 三个拱门 | `BeamGroundHalfWidth = 3.75` |
| 段间距 / 冲刺耗时 | 1.75~1.81 单位 / 0.58~0.60 秒 | |
| 离线模拟(完美预判) | **✓ 17.1 秒通关、0 失误** | 双片比单片(12.8 秒)难一档 |

### 18.2 角色躲进遮罩区要一起调暗

遮罩 `bg_gate_shadow.png` 是 alpha≈100/255 的半透明黑 ⇒ 场景被压到 **×0.608**；
但角色画在遮罩**之上**，不跟着压就会"浮"在暗影里。

`EyeCorridorLaserPuzzle.ApplyPlayerDim()`：`PlayerInGate` 时把角色所有
`SpriteRenderer.color` 乘 `ShadowDim`（默认 **0.60**，就是那个 0.608），离开时回到 1。

- 首次抓取时缓存**基准色**（角色身上已经有 PlayerBuilder 叠的冷调 0.68/0.72/0.78，
  不能直接覆盖），之后只写 `基准色 × 系数`，alpha 不动。
- 角色被 PlayerBuilder 重建（换形态）时重新抓取，并把"已施加的压暗"除回去，避免越压越黑。
- 对照图：`docs/千眼回廊/角色暗影调光_对照.png`

### 18.3 光束太亮、像一束小激光 ⇒ 改成一片散光

三个原因一起改：

| | 旧 | 新 |
|---|---|---|
| 高亮内核 | 还有一层收窄 34% 的芯，alpha **0.68**（加色后 ≈1.36 → 直接烧白） | **删掉** |
| 光雾亮度 | 0.30（加色 ≈0.60） | **0.11**（≈0.22） |
| 横向剖面 | `(1-\|2u-1\|)²` 平方衰减，中心亮、边也硬 | `SmoothStep(0,1,e)` **纯柔边**，无平台 |
| 纵向 | 越靠铜眼越实（顶点最亮 → 过曝） | mesh **顶点色**把顶点压到 `BeamApexFade = 0.50` |
| 颗粒 | 无 | 两级值噪声 `BeamGrain = 0.14`，读起来是"散光"不是塑料板 |
| 危险边界怎么读 | 靠内核 | **地面亮条** `~beam_spot`（中间平台 + 两端柔降，alpha 0.22） |

「散光是散的、边界必须硬」——所以把**读数职责从光锥本体搬到地面亮条**上。
对照图：`docs/千眼回廊/光束观感对照_旧vs新.png`（+ `_局部放大`）。

本轮恢复：

```

       → 底部对白条播 D_02「目困莽夫,身陷焦土。」+「见影即止,避瞳而行。」→ 解锁
```

## 20. 修掉「非光照区域也有泛光」—— 地面亮条被放大了 2 倍（2026-09-14 晚）

用户：「为什么非光照区域也有泛光效果，你清除一下」

### 20.1 病根

`GroundBarSprite()` 生成的是 **256×128** 贴图，但 `MakeSprite(tex, pivot, Hh)` 传的 ppu 是
**Hh = 128** ⇒ 精灵实际尺寸 **2×1 世界单位**（注释却写着 "1×1 单位"）。
而 `SyncBeamVisual()` 是直接 `localScale = (barW, 1.30)` 当世界尺寸用的，`barW = 3.75×2×1.06 = 7.95`
⇒ 实机渲染宽度 **15.90 单位（1590px）**，危险带只有 **7.50 单位（750px）**。

再叠上 `BeamBarEdge = 0.14`（span = 0.28）：平台（alpha=1 的最亮段）占半宽的 72%
⇒ **平台宽 11.45 单位**，即

| | 宽度 | 边界 |
|---|---|---|
| 危险判定带 | 7.50 单位 | ±3.75 |
| 地面亮条整体 | 15.90 单位 | ±7.95（溢出 4.20/侧） |
| 亮条里**最亮**的平台段 | 11.45 单位 | ±5.72（**溢出 1.97/侧**） |

于是玩家会站在一段"亮得很明显"的地面上却完全安全 —— 那段地板根本没被光锥照到。
（注：出生点 −16.45 其实没被照亮，那里离亮条边缘只有 0.8 单位、alpha 已近乎 0；
真正显眼的是**光锥两侧各约 2 单位的满亮地板**。）

### 20.2 改法

1. `GroundBarSprite()` 改成 **S×S 方形贴图 + ppu = S** ⇒ 严格 **1×1 世界单位**
   （纵向尺寸不变：仍是 1 单位 × localScale 1.30 = 1.3 单位高）。
2. 删掉 `BeamBarEdge`，改由几何反推柔降：`plateau = 1 / BarBleed = 0.943`
   ⇒ **平台边界严格落在 ±BeamGroundHalfWidth = ±3.750**，与危险判定线**完全重合**
   （实测：平台 7.50 = 危险带 7.50）。平台以外只剩 0.23 单位（23px）做柔降。
3. `BarBleed = 1.06f` 提成具名常量，`barW` 与 `plateau` 共用同一个来源，不会再各算各的。

**副产品（好事）**：以前"看得到的亮"比"会死的地方"每侧宽 1.97 单位，判定和视觉互相骗人；
现在亮条平台 = 危险带，玩家读边界就是读判定。

### 20.4 顺带排查（都不是病根，记录以免下次重复怀疑）

- **铜眼光晕** `_eyeGlow`：GlowSprite 是 256×256 + ppu=128 ⇒ 精灵 2×2 单位，`localScale = 2.2`
  ⇒ 直径 **4.40 单位**。但加色是 `Blend SrcAlpha One` ⇒ 实际贡献 = `alpha × texA²`、
  `texA = (1-d)³` ⇒ 衰减是 **(1-d)⁶**：中心 +76/255，d=0.2 就只剩 +20，d=0.4 几乎看不见。
  所以它是一团**紧贴铜眼**的光，不是墙上的一片泛光 —— 不用动。
- **没有后处理**：项目是内置管线，全局搜 `Bloom/PostProcess/Volume` 为 0 命中，
  相机也没有 Bloom。所以"泛光"只可能来自这些加色精灵/mesh，不可能来自后期。
- **场景文件**里没有任何 SpriteRenderer（全部运行期构建），没有遗留的发光对象。
