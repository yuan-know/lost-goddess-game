## 过程记录

### 为什么圆窗一开始看不清

- 齿轮素材 500×500（内容 378×376），盘面有 **5 个正五边形排布的圆窗**
  （窗半径 ~40，窗心半径 ~105），每窗内画着对应道具的**深色小图标**，
  圆窗本身是**透明的**（alpha≤8 共 162611px）。
- 齿轮按 `kGearOffsetY = -180` 挂在容器底边下方 → 屏幕范围 y −239..281，
  而容器条带是 y 201..879，**齿轮几乎整块落在下方黑边里**，
  圆窗透出来的是纯黑，深色图标读不出来。
- 想靠「背后垫背景砖墙」救是死路：背景原图自身最下 5% 行平均亮度只有 **5.6**
  （整幅 24.3），那个高度没有可用的亮砖。

### 走过的弯路（两次都被否）

1. **珐琅盘**（`修法对比_齿轮局部_0_A_B.png` 里的 A 方案）：
   往窗里填不透明暖白盘。图标确实清楚了，但看起来像一块白板贴在齿轮上，
   和场景格格不入 —— 用户否掉。
   还有两个技术教训：
   - 只填 `alpha<=8` 会留斑驳残留，必须按标准 alpha 合成（底板垫在部件下面）；
   - 五点拟合估窗心会偏，造成**缺口**。改用「透明环 ∪ 图标」并集质心迭代，
     5 个窗心 + 半径都收敛得很好（窗半径 39.6~42.4）。
2. **v1 满窗柔光 / v2 纯边缘辉光**（`泛光对比_第二轮.png` 前两格）：
   v1 图标清楚但偏奶白盘；v2 光圈漂亮但图标在暗心读不出来。

### 定稿剖面（v7）

```
# 先用「非金属像素」反推每个孔的真实孔径与圆心（不是透明环外沿！）
hole   = (~metal) & (d <= 58)          # 孔 = 孔内透明环 + 图标,两者都不是金属
迭代 hole 的质心 → 孔心; 孔径 = hole 像素到孔心的最大距离
5 个孔量出来 41.5~41.7 → 统一取最大值,保证大小一致

glow = CORE_A * (1 - smoothstep(0.92*r, 1.18*r, d))    # 孔内全亮,孔缘外才衰减
     + RIM_A * exp(-((d - r)/6)^2)                      # 孔缘辉光,勾出孔的边界
     + AMB   * (1 - smoothstep(0.5*r, 1.7*r, d))        # 很淡的整体泛光
整体再 GaussianBlur(1.0) 消硬边
不透明金属区: rgb += GLOW_RGB * glow * 0.55             # 回光溅到铜面上
透明/半透明区: rgb = 部件*ga + 辉光*(1-ga);  a = ga + 辉光*(1-ga)
```

⚠ 上一版(v6)的教训：`smoothstep(0.30r, 0.80r)` 让辉光在 0.8r 就没了，
**光圈比孔小一圈**；而且孔径是用「透明环外沿」估的（39.6~42.4，被图标切碎后偏小），
正确做法是用**非金属像素**反推（41.5~41.7，5 个孔高度一致）。

### 小旋钮「扭不动」

上一轮我给旋钮加的圆心死区 `KnobMinRadiusPx=46px` 太大：旋钮素材内容半径只有
194/500，显示 160px 时**可见半径仅约 62px**，死区吃掉旋钮面 74%。
已改成 **12px**（只避开圆心奇点），单帧角度变化 >90° 一律当伪信号重新取基准。
调试场景加 `9`/`0` 实时调死区。

**顺带观察**：旋钮素材四周透明留白很大，`kKnobSize=160` 时屏幕可见直径只有 ~124px，
作拖拽目标偏小；想让可见直径就是 160px，`kKnobSize` 要设到约 **206**。
